# ORCA Max Mouny — تنفيذ القسم 21

هذه الوثيقة تسجل تنفيذ الطبقة الفوقية للاكتشاف الذاتي للاستراتيجيات والمناعة التكيفية ضد المخاطر غير المرصودة. كلمة **منفذ** تعني كودًا قابلًا للتشغيل مع اختبار محلي أو تحقق بيانات موثق؛ ولا تعني تفوقًا إحصائيًا أو جاهزية Live.

| البند | التنفيذ | الحالة الواقعية والحدود |
|---|---|---|
| 21.1 اكتشاف alpha | `analytics/alpha_discovery.py` يولد مرشحين من تعبيرات مقيدة وحقول سوق معروفة | منفذ عازل؛ 16 مرشحًا على 1000 شمعة، وصفر مؤهل للتنفيذ. لا يستطيع منح authority أو تجاوز بوابات المخاطر. |
| 21.2 السببية | `analytics/causal.py` يحسب Granger-style score وTransfer Entropy واتجاهًا وآلية اقتصادية معلنة | منفذ تشخيصي. على عينة BTC الحالية ظهر اتجاه تشخيصي 1h→2h، ولا يُعامل كسبب اقتصادي مثبت أو كإشارة Live. |
| 21.3 الخبراء ونقاط التحول | `analytics/online_experts.py` يستخدم Beta beliefs لمزج توقعات الخبراء وتحديثها بعد النتيجة، مع rolling error shift | منفذ واختبار محلي. الإنذار input للمراجعة، وليس تغييرًا مستقلًا في الحجم أو الحدود. |
| 21.4 الضغط التوليدي/العدائي | `analytics/stress_generator.py` يستخدم block bootstrap من العوائد الفعلية مع overlay هبوطي محافظ | منفذ بصيغة إحصائية قابلة للتدقيق؛ ليس TimeGAN ولا نموذجًا توليديًا عميقًا. الإجراء الوحيد هو اقتراح/تفعيل تشديد التوقف، ولا يسمح بتخفيف حد. |
| 21.5 CVaR/EVT | `analytics/tail_risk.py` يحسب VaR وCVaR وذيل EVT محافظًا | منفذ واختبار. التقرير الواقعي: VaR 0.4587%، CVaR 0.7544%، EVT tail loss 0.5948% على 999 عائدًا؛ هذه تشخيصات وليست ضمانات. |
| 21.6 عدوى المنصات | `analytics/contagion.py` يحسب الارتباط، centrality، الأصول المتأثرة، وترتيب الخروج | منفذ واختبار. القرار الآلي المسموح هو تقليل التعرض/أولوية السيولة/التنبيه فقط؛ لا توجد آلية زيادة تعرض. |
| 21.7 الشرح والانجراف | `analytics/explainability.py` يوفر permutation importance وPSI/JSD | منفذ واختبار. PSI المرتفع يذهب إلى مراجعة أوزان/تقاعد القسم 20؛ لا يوجد تقاعد مستقل للقسم 21. |
| 21.8 الحوكمة | `analytics/governance21.py` يفرض causal وCPCV/PBO/DSR وshadow وtail checks، ويربط Kill-Switch | منفذ واختبار. حتى إذا اجتازت المعايير، `execution_eligible=False` دائمًا وLive authority غير موجودة. Kill-Switch يوقف الطبقة fail-closed. |
| 21.9 التكامل مع القسم 20 | نتائج الانجراف والنتائج التشغيلية تغذي المراجعة، الأوزان، shadow، والتقاعد في Section20Layer | منفذ على مستوى الواجهات والحوكمة؛ حدود الخطر الأساسية لا تُعدّل آليًا ولا تُرخى. يلزم تشغيل مستمر على جهاز المستخدم لتجميع تاريخ طويل. |
| 21.10 الإفصاح | التقارير تسجل المصدر والعدد والأوامر والمفاتيح والقيود | منفذ. لا وعود ربح أو تحسن Win Rate أو جاهزية Live. |

## تحقق Binance العام في 26 أغسطس 2026

شغّل `scripts/orca_section21_real.py` باستخدام REST العام لـBinance، فتم جلب **1000 شمعة BTC/USDT، 1h** من 15 يوليو 2026 13:00 UTC إلى 26 أغسطس 2026 04:00 UTC. لم يستخدم السكربت مفاتيح أو Sandbox ولم يرسل أمرًا؛ سجل `orders_submitted=0` و`live_authority=false` و`keys_used=false`.

| المقياس | النتيجة |
|---|---:|
| مرشحو alpha | 16 |
| المؤهلون للتنفيذ | 0 |
| العوائد المستخدمة | 999 |
| CVaR 95% | 0.7544% |
| أسوأ سحب في 24 سيناريو ضغط | 32.3411% |
| جميع سيناريوهات الضغط تفرض تشديدًا | نعم |
| تحذير الانجراف | نعم؛ PSI = 0.2656 |
| قرار الحوكمة | مرفوض للمراجعة التنفيذية؛ CPCV/PBO/DSR وshadow غير مجتازة |

النتائج لا تمثل Backtest كاملًا ولا مقارنة OOS محسنة. لذلك لا توجد دعوى بتحسن الأداء، ولا ترقية استراتيجية، ولا انتقال إلى Live. التقرير الخام محفوظ في [`section21_report_2026-08-26.json`](section21_report_2026-08-26.json).

## الأمن والتشغيل

الوضع الافتراضي يظل Paper. لا تُحفظ مفاتيح التداول في Git أو التقرير، ولا يمنح القسم 21 أي صلاحية مباشرة لإرسال أوامر Live. يتطلب Sandbox مفتاحًا صادرًا من المنصة ويُدخل محليًا على Windows عبر keyring؛ ويتطلب Live اعتماد المستخدم ومرور البوابات والمراجعة المستقلة، وهو غير متاح أو مُتحقق في هذه البيئة.
